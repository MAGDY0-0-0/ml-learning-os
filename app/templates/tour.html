How this works

Two minutes. Then start M0.

1 · The roadmap is measured in units, not weeks

Ten modules, 32 units, 104 curated resources. Each unit is one sitting (30–120 min). Because your available hours vary a lot, nothing has a due date and nothing turns red. A heavy college week means one unit; a light week means five.

M0 setup → M1 build this app → M2 data → M3 math recap → M4 classical ML → M5 deep learning → M6 transformers → M7 LLM engineering → M8 MLOps → M9 portfolio.

2 · Every unit leads with video, and nothing is a single point of failure

You said you learn best from video, so the primary resource is a video wherever a good free one exists — the build fails validation otherwise. Every unit carries at least three resources spanning different formats, so hitting Swap moves you between a video, a written explanation, and something interactive — not just to another video you'll dislike for the same reason.

Each resource shows an honest ✓ verdict and a ⚠ caveat, so you always know why it's recommended and what's wrong with it.

3 · The Rigor Ladder is the actual differentiator

split → leakage audit → baseline → metric → error analysis → ablation → reproducibility.

This recurs in every module and is enforced: a project cannot be marked complete while any check is outstanding. The leakage audit uses the 8-type taxonomy from Kapoor & Narayanan, who found leakage in 329 papers across 17 fields. Skipping a check demands a written justification, which lands in inbox/ for Claude to push back on.

4 · Ask for help from anywhere

Every unit, submission and rubric item has an Ask Claude button. It builds a complete prompt — objective, your notes, your code, test output — and writes it to inbox/. Then just tell Claude "check my inbox". No API key needed, no cost.

5 · Submit code and get it actually checked

Assignments run against hidden tests in a sandboxed subprocess with a hard timeout and no network. Then one click requests a real code review.

6 · The library answers from your own books

Drop PDFs into A:\ml\library\ and reindex. Search returns the passage with its page number. You can also pull new papers from arXiv and Open Library without leaving the app.

7 · The portfolio bar is a deployed demo

Reviewers spend under two minutes on a repo, and a live link is the strongest single signal. So at least one project must ship all three: GitHub with an honest README, a Hugging Face model + dataset, and a demo a stranger can click.

إزاي تستخدم الموقع

اقرا الصفحة دي في دقيقتين، وبعدها ابدأ من M0.

١ · الخطة بالوحدات، مش بالأسابيع

عندك ١٠ موديولات، و٣٢ وحدة، و١٠٤ مصدر مختار بعناية. كل وحدة = جلسة واحدة (من ٣٠ لـ ١٢٠ دقيقة).

عشان وقتك بيتغير من أسبوع للتاني، مفيش أي مواعيد نهائية ومفيش حاجة هتبقى حمرا لو غبت. أسبوع الامتحانات = وحدة واحدة. أسبوع فاضي = خمس وحدات. ده مصمم كده مخصوص.

M0 التجهيز ← M1 تبني الموقع ده ← M2 البيانات ← M3 مراجعة رياضة ← M4 تعلم الآلة الكلاسيكي ← M5 التعلم العميق ← M6 المحوّلات (Transformers) ← M7 هندسة نماذج اللغة ← M8 التشغيل والنشر ← M9 معرض أعمالك.

٢ · كل وحدة بتبدأ بفيديو، ومفيش مصدر واحد بس

إنت قلت لي إنك بتتعلم من الفيديو أحسن، فالمصدر الأساسي في كل وحدة فيديو طول ما فيه واحد كويس ومجاني.

كل وحدة فيها ٣ مصادر على الأقل بصيغ مختلفة. يعني لما تدوس زرار Swap، الموقع هيوديك من الفيديو لشرح مكتوب أو تفاعلي — مش هيجيب لك فيديو تاني هيزهقك بنفس الطريقة.

وتحت كل مصدر سطرين بيقولوا لك الحقيقة:
✓ الأخضر = ليه المصدر ده كويس ورأي الناس فيه.
⚠ الأصفر = عيوبه وإيه اللي ناقص فيه، عشان تكون عارف من الأول.

٣ · «سلّم الدقة» هو اللي هيفرّقك عن غيرك

تقسيم البيانات ← فحص التسريب ← خط أساس ← اختيار المقياس ← تحليل الأخطاء ← اختبار المكوّنات ← إعادة الإنتاج.

ده بيتكرر في كل موديول، والموقع مطبّقه بالإجبار: مش هتعرف تقفل أي مشروع طالما في فحص واحد لسه مخلصتهوش.

فحص التسريب (Data Leakage) مبني على تصنيف من بحث علمي لقى أخطاء تسريب في ٣٢٩ بحث في ١٧ مجال مختلف. ولو حبيت تتخطى فحص، لازم تكتب سبب مكتوب، والسبب ده بيوصل لـ Claude عشان يراجعه ويقول لك لو كلامك مش مظبوط.

دي أهم حاجة في المنهج كله. ناس كتير بتعرف تدرّب موديل، بس قليل اللي يعرف يجاوب: «إزاي أتأكد إن النتيجة دي حقيقية؟»

٤ · اسألني من أي مكان في الموقع

في زرار Ask Claude في كل وحدة، وكل واجب، وكل بند فحص.

لما تدوس عليه، الموقع بيجهّز سؤال كامل فيه: هدف الوحدة + ملاحظاتك + الكود بتاعك + نتيجة الاختبارات + سؤالك. وبيحفظه في فولدر inbox/.

بعد كده ارجع لـ Claude وقول له: check my inbox — وهيجاوبك وهو فاهم إنت واقف فين بالظبط.

مش محتاج أي مفتاح API، ومش هيكلّفك فلوس خالص.

٥ · سلّم كودك واتصحّح فعلاً

في ٧ واجبات جاهزة. اكتب الحل، ودوس Run hidden tests، والموقع هيقول لك مثلاً 8/11 passed يعني نجحت في ٨ اختبارات من ١١.

بعدها دوس Request Claude review عشان أراجع الكود نفسه، مش بس النتيجة.

متقلقش لو كتبت كود غلط أو دخلت في لوب لا نهائي — الكود بيشتغل في مكان معزول، والإنترنت مقفول عليه، وبيقف لوحده بعد ٣٠ ثانية. مش هيبوّظ حاجة.

٦ · المكتبة بتجاوبك من كتبك إنت

حط أي كتاب أو بحث PDF في الفولدر A:\ml\library\، وبعدين ارجع للموقع ودوس Reindex PDFs.

بعد كده دوّر على أي كلمة، والموقع هيجيب لك الفقرة ومعاها رقم الصفحة بالظبط.

وكمان تقدر تدوّر في arXiv (أبحاث) وOpen Library (كتب) من نفس الصفحة من غير ما تسيب الموقع.

٧ · مشروعك لازم يبقى شغّال على النت

اللي بيوظّف بيبص على الكود أقل من دقيقتين، وأقوى حاجة ممكن تعرضها هي لينك شغّال الناس تقدر تجربه.

عشان كده لازم مشروع واحد على الأقل يبقى فيه التلاتة:

١) GitHub — بشرح واضح، وفيه كمان اللي فشل معاك مش بس اللي نجح.
٢) Hugging Face — الموديل والبيانات، مع توضيح أمين لحدود الموديل.
٣) لينك شغّال — أي حد يفتحه ويجربه.

المشروع اللي بيقف عند «النتيجة كانت كويسة» من غير نشر، بيتقري على إنه بحث نظري، مش شغل مهندس.

٨ · نصيحتين مهمين

المراجعة أهم من السرعة. ٥ دقايق كل يوم في صفحة Review أحسن بكتير من إنك تخلص موديول وتنساه بعد شهر.

متضيّعش وقت في الرياضة. موديول M3 وحدتين بس (حوالي ساعة). اقرا الورقة، وعلّم بس على اللي نسيته فعلاً. لو مفيش حاجة نسيتها، عدّي على طول لـ M4. متتفرجش على البلاي ليست كلها — ده أكتر سبب بيضيّع وقت اللي بيتعلم لوحده.
